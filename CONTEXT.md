# GitCthulhu

Desktop Git client. The window is iced. Git work goes through a port; one adapter implements it.

## Terms

**Port.** `GitRepository` in `core_domain`. Sync methods. The window depends on this interface, not on gitoxide.

**Adapter.** `GitoxideAdapter` in `git_adapter`. Reads history, branches, and status with gix. Checkout, stage, unstage, and commit go through the `git` executable, because gix 0.66 keeps the worktree options those commands need private.

**Composition root.** The `app` crate. The only module that constructs `GitoxideAdapter` and `ConfyConfigStore`, and passes the repository port into `gui_app::run`. `gui_app` does not depend on `git_adapter` or `config_adapter`.

**Opening a repository.** Open…, a recent repository, Init and Clone all end in one background open: the opener validates the folder (`discover`) and only then remembers it, and the first load (status, history, branches, stashes, tags) runs on the same worker. The workspace on screen is replaced only after that succeeds. While it runs a banner under the tabs (and on the welcome screen) says "Opening name… n s"; if it fails, the banner names the stage that failed (opening or reading) with Retry, Copy diagnostics and Dismiss, and the open tabs, drafts and selection are untouched. Diagnostics hold the version, stage, path, duration, the last completed operation and git's message, with URL credentials removed. A panic writes a crash report under `%LOCALAPPDATA%\git_cthulhu\crashes` (the program still ends; nothing is caught). Release builds unwind, so a worker thread that panics ends its one job with an error instead of closing the window.

**Welcome screen.** `GitApp` with no adapter. Shown when there is no command-line path and no remembered repository that can still be opened. Open Repository asks for a folder, then the composition root's opener builds the port and stores that path.

**Repository view.** `GitApp` holding one or more sessions, each with an `Arc<dyn GitRepository + Send + Sync>`. Shown when a path was passed on the command line, after Open Repository succeeds, or when the remembered folder is still a repository. Loads status, the newest 50 commits from every local branch, and branches as soon as the window has a repository.

**View event.** `ViewEvent`. The only input to `AppState::apply_event`. Status, log, branches, settings, and errors. The reducer does not call an adapter or choose the next task. The window does.

**Worktree edit.** Stage, unstage, or commit of whole paths. Runs on a worker thread, then refreshes the repository view.

**Fake repository.** `test_support::FakeGitRepository`. A port implementation whose results are set by the test. Used by `gui_app` tests. Not a dependency of the running binary.

## What a session can do

Open a repository from the command line or from the welcome screen's folder dialog. Init a folder that is not already a repository, or clone a URL into a new directory under a chosen parent, then open that path the same way. Clone uses the user's `git clone` and does not sign in to a provider. Reopen the last of those paths on the next launch when it is still a repository. The header shows that path and an Open… control, so a second folder replaces the one on screen. Show branches, a 50-commit graph of every local branch (and a detached HEAD), the changes list, and one line for the current branch: its upstream and how many commits it is ahead or behind. Check out a local branch. Stage, unstage, and commit whole paths. Fetch the default remote, push the current branch to its upstream, and pull with `--ff-only`, using the user's git. Stash changes (all, or the selected files; optionally with untracked files and a message), and apply, pop, or drop one stash from the branch tree. Drop asks first. Untracked files stay in the worktree. Create a branch at the selected tip, a remote branch, a tag or a commit, and check it out unless Checkout branch is cleared, rename a local branch, and delete a merged branch that is not current. Delete asks first. An unmerged branch is left, with git's own message. Tags that point at a commit appear in the refs list, and only when there is at least one. Selecting a tag reads that commit's patch. The refs, history, and changes columns can be dragged wider or narrower. Refs and changes can each collapse to a rail on that side and open again at the width they had. A commit can be cherry-picked onto the current branch, or the current branch can be reset to it: soft, mixed, or hard. Hard discards the worktree. Another branch can be merged (fast-forward when possible, or `--no-ff`), or the current branch can be rebased onto it. Each of those asks first. A conflict leaves the operation in progress with the conflicted files listed; see Merge and conflicts.

## Worktree sessions

**Session.** `WorktreeSession` in `gui_app`. One open worktree path with its own `GitRepository` port and its own `AppState` (status, commits, branches, stashes, tags) plus its UI state: selection, commit message, marked files, and the loaded diff. `GitApp` holds a list of sessions and the index of the active one. Switching tabs moves that index; it does not reload. Each session has a `SessionId` that is never reused in the process. A background job carries the `SessionKey` (id and path) of the session that started it, and its result is dropped unless that same session is still open, so a tab closed and reopened on the same folder, or a repository opened again, never receives an older session's result.

**Tab strip.** Sits under the top bar, one tab per open session. Click to switch, close a tab with its close control (the last tab stays, and so does a tab with a job running). A `+` control opens a picker over the catalogue.

**Catalogue.** The list from `git worktree list --porcelain`, read through `GitRepository::worktrees` and shown in the Files column's Worktrees section. A linked worktree opens into a tab from there or from the picker. Create adds a worktree for a named branch at a chosen folder, creating the branch when asked. Remove asks first and has a force option for a dirty tree. The main worktree cannot be removed.

**Retention.** The setting for what a tab keeps when you leave it: full (message, marks, selection), partial (message and marks; selection cleared, the default), or path only (nothing but the path). Set in Settings and stored with the other settings.

**Opener.** `RepositoryOpener` is for Open… and remembers the folder as `last_repo_path`. `WorktreeOpener` is for tabs and does not, so opening a linked worktree never changes which repository the next launch reopens. The composition root builds both; `gui_app` names neither adapter.

**WIP rows.** The history graph shows one Working changes row for each worktree with staged, unstaged, untracked or conflicted paths, at the top: open tabs in tab order, then worktrees with no tab in catalogue order. A worktree with no tab is read through a transient adapter that the `WorktreeOpener` builds for one `status` call (`jobs::probe_worktree_in_background`), each time the catalogue loads and when its tab closes. Each read carries a generation, and a read that lands after a newer one, or after the worktree left the catalogue or gained a tab, is dropped. A worktree whose folder is gone shows no row. The row reads "Working changes · n files" and an outlined pill "WIP · branch · folder" ("detached" for a detached HEAD) with the edit mark, so it never passes for a branch or tag pill. The active worktree's pill is in the accent colour and says "active". When two worktrees have folders of the same name, the label adds parent folders until they differ (`a/wt`, `b/wt`; `wip::folder_labels`); the Explorer uses the same names. Hovering a row shows the full path, branch and HEAD. A single click inspects the worktree, a double-click opens it in a tab. Under a branch filter or search only the active worktree's row shows, and the inspected one always does.

## Finding things

**Log layout.** The default pane preset, after the JetBrains Git log: branch tree on the left, History in the middle with the Inspector beside it, and a full-width Diff below. The terminal starts collapsed. The top bar's layout control still cycles the other three presets.

**Branch tree.** The Explorer column. One filter box and one scroll over HEAD, Local, Remote, Worktrees, Stashes and Tags. Branch names fold into folders at each `/`; folders inside a remote start closed. A click filters the log to that branch, a double-click checks a local branch out, and every other action is on the row's right-click menu: new branch from a local or remote branch (checkout optional), checkout of a remote (creating the tracking branch), merge, rebase, rename, delete, and for worktrees open, new, open folder, copy path and remove. A click on a worktree inspects it and a double-click opens its tab. Ref pills in the History table clip to a quarter of the Description column; hovering them lists every ref at that commit by full name, with the worktree folder where one is checked out, so a clipped "feature/" is always readable.

**Log filter bar.** Above the History table: text search, Branch ▾ (All, HEAD, any local or remote branch), User ▾ (authors of the loaded commits) and the current-branch toggle. Dates are shown in UTC, because the crate reads no time zone. Merge commits are muted.

**Inspect and activate.** Inspecting a worktree shows it in the Inspector without moving the active tab, the terminal folder or the mutation target (`GitApp.inspect`, beside `active`). A single click on a WIP row or an Explorer worktree row inspects, and so does Enter on a Quick open worktree. A double-click, Open in tab, the tab strip and "Open worktree in new tab" activate (`Message::OpenWorktree`). Inspecting the active worktree shows its working tree as before. A dirty worktree shows its Staged, Changes, Unversioned Files and Merge Conflicts as plain lists; a clean one selects its branch tip as a commit of the active tab, because the history is shared. The Inspector head reads "Inspecting WIP · branch · folder" with Open in tab and Back, and none of the selection's commands: stage, unstage and commit appear only for the active worktree. Choosing anything else, switching tabs or Back ends inspection. Filters are never cleared to show the inspected worktree.

**Inspector.** A commit, tag or stash shows its changed files as a folder tree with line counts, with its details (hash, author, date, parents, refs) below. Any other selection shows the working tree, laid out like the JetBrains Commit window: a toolbar on top, then the files (the only part that scrolls) in Staged, Changes and Unversioned Files, then the commit message with Suggest and Commit. File names are coloured by change kind: blue modified, green added, grey deleted, red unversioned. A folder holding only one folder is joined to it on one row. The head names the selection and lists its commands as labelled buttons.

**Diff.** Side by side by default, after the JetBrains diff viewer. Removed and added runs are paired into modified rows (blue, with the changed words marked), unpaired lines are added (green) or removed (red) against an empty filler, and both gutters show line numbers. The head steps through differences (↑ ↓ n/N) and files (‹ n/N files ›) and switches to unified. `crate::diff_view` works the rows out before drawing, with fixed row heights, so jumping to a difference is a computed scroll offset.

**Branches popup.** The top-bar branch chip opens it, after the JetBrains Git branches popup: a search field, New Branch… (from HEAD, checkout ticked) and Merge into Current…, then the local and remote branches with ahead/behind. A branch opens its own menu: checkout, new branch from it, merge, rebase, rename, delete.

**Working-tree selection.** Click selects one file and shows its diff, Ctrl-click (Cmd on macOS) toggles a file, Shift-click selects the range from the last click in the order the files are drawn. The check boxes show the same selection. Right-click acts on the selection: stage, unstage, discard, stash, ignore, untrack, copy paths. Each counts only the files it applies to. Right-clicking outside the selection selects that row first. Discard asks once for everything selected, staged or not.

**Stash dialog.** Stash (top bar) and "Stash N files…" (right-click) ask for an optional message first. Stashing everything can include untracked files.

**Merge and conflicts.** Merge into Current… opens a dialog: pick the branch, and optionally always record a merge commit (`--no-ff`); otherwise git fast-forwards when it can. When files conflict, the merge stays in progress. `RepoStatus.operation` reports it, and a bar under the tabs says how many files still conflict, with Commit merge (enabled once none are left) and Abort merge. The same bar covers a stopped rebase, cherry-pick or revert with Continue and Abort. Conflicted files are listed under Merge Conflicts (`RepoStatus.conflicted_files`, never as staged deletions), each with Yours, Theirs and Resolved (after editing the file by hand), also on right-click.

**Change kind.** `RepoStatus.kinds` (`ChangeKinds` in `core_domain`) says how each staged or unstaged path changed: added, modified, deleted, renamed or conflicted. Untracked paths are unversioned. A path with no entry reads as modified, so an adapter that does not classify still reports something true.

**Icons.** Every icon comes from Codicons (`gui_app/assets/fonts/codicon.ttf`, CC BY 4.0), compiled into the binary and named by `icons::Icon`. Icons no longer depend on the fonts installed on the machine; a test checks every codepoint is in the font.

**Window resizing.** The Explorer keeps the pixel width you gave it when the window is resized (280 px to start, within 16–36 % of the width). The log and the Diff take up the difference.

**History search.** The log filter bar's text field (Ctrl+K) narrows the history table to loaded commits whose message, author, hash prefix, or tip ref name contains every typed term. Matches show their lane dot without lines, and a line under the headers says how many of the loaded commits matched. It searches what is loaded, not the whole repository.

**Quick open.** Ctrl+P opens one field over branches, remotes, worktrees, tags, stashes, changed files, loaded commits, and recent repositories, ranked by a subsequence score that favours word starts. A prefix scopes it: `b:` `t:` `s:` `w:` `c:` `f:` `r:`. Enter selects a branch, tag, stash, commit, or file (nothing is checked out), inspects a worktree (open it in a tab from the Inspector head), or opens a repository. Esc, Ctrl+P, and Ctrl+K work while a text field has focus.

**Recent repositories.** `recent_repositories` in the settings, newest first, at most 24. The repository opener and a command-line path add to it; worktree tabs do not. The welcome screen lists them, the top bar's Recent opens Quick open on `r:`, and the Repositories column shows them all.

**Header.** Two rows. The title row holds the header mark, the repository's folder name and full path, then Recent, Open… and Settings. The branch row has three slots: the branch chip and tracking line on the left, Compare and the view switches on the right, and between them, on the window's centre line, Fetch, Pull ↓n, Push ↑n and Stash (n files). The two sides share the spare width equally and clip, so a long branch name or narrow window never moves the group. The counts come from the same tracking state as the tracking line: "…" while loading (never 0), plain Pull and Push, disabled, when the branch has no upstream. While an action runs its button reads Fetching…, Pulling… or Pushing… and the others wait; a disabled button says why on hover. In the branch tree a branch shows ↑ahead ↓behind, and a long name clips instead of pushing the counts onto a second line. The chip has a row of its own so a long path can never push it. The header mark (`HeaderMark` in `core_domain`) is chosen under Settings → Appearance: two-tone, badge and name, spaced capitals, shell prompt, or badge only.

**Repositories column.** Left of everything below the header. Lists the recent repositories with a filter; a click opens one, × forgets it (the folder is left alone). Pinned (`repositories_pinned`, the default) it is a column; unpinned it folds to a rail of initials whose top button shows the list over the window. The Explorer keeps its pixel width when the column is pinned or unpinned, because pane ratios are taken against the pane grid, not the window.

**Terminal.** A real interactive shell under the workspace: `pwsh` (else Windows PowerShell; the user's `$SHELL` elsewhere) running on a pseudoconsole (ConPTY on Windows), with alacritty's terminal emulation drawn by the `terminal_widget` crate (vendored from iced_term 0.6, MIT). Tab completion, history, colours, cursor movement and interactive programs are the shell's own, and the profile loads as in any terminal. It starts in the open repository's folder the first time the panel opens and lives as long as the window: folding the panel or opening another repository keeps it. A click inside gives it the keyboard; a click anywhere else gives the keyboard back. The whole panel bar folds and unfolds the panel; its buttons take their own clicks. Clear sends Ctrl+L (the shell's clear-screen), Ctrl+` shows or hides it, and the top edge drags to resize. When the shell exits, a click starts a new one.

**Compare.** One file, two versions, side by side (or unified). Opened from Compare in the branch row, or Resolve… on a conflicted file. Either side is the working tree, HEAD, a branch, a tag, any typed commit, or for a conflict the base, yours (`:2`) or theirs (`:3`). A conflicted file opens on yours against theirs with Accept yours, Accept theirs and Mark resolved; any other file opens on HEAD against the working tree. Both sides are read in working-tree form (`git cat-file --filters`) and diffed with `git diff --no-index`, so line endings do not show as changes. A working tree on the left is asked of git the other way round and the diff reversed.

**Activity log.** Every action records an entry in the open repository's log: fetch, pull, push, checkout, stage, unstage, untrack, commit, discard, ignore, hunk edits, stash push/apply/pop/drop, branch create/rename/delete, merge, rebase, cherry-pick, reset, abort/continue, conflict resolution, worktree add/remove, and each terminal command. An entry has the time (UTC), a title, what it acted on, the git command it amounts to, how long it took, and how it ended: done, failed with git's message, or stopped. Worktree tabs write to the repository's log and name their worktree. While an action runs the status bar shows it with its running time; when it ends the status bar shows done or failed for six seconds. Clicking the status bar opens the Activity tab beside Terminal in the bottom panel: newest first, failures tinted, with Only failures and Clear log. The tab counts failures since the repository was opened. Logs are kept between runs through the `ActivityStore` port; `config_adapter::JsonlActivityStore` writes one JSON-lines file per repository under `activity/` beside the settings file, keeps the newest 500, and skips a damaged line instead of losing the log. Each action's entry is closed in one place, `finished_outcome` in `app.rs`, which lists every finish message.

**Untrack.** Right-click a tracked file, folder or selection: Untrack (keep on disk) runs `git rm --cached -r`; Untrack and ignore also appends the path to `.gitignore`. The file stays on disk and shows as unversioned; the next commit records the removal. Git refuses a file whose staged version differs from both HEAD and the disk, so no staged work is lost.

### Later: several repositories

A session is a worktree of the repository that was opened. Unrelated clones in one window are not covered. `last_repo_path` is still the one path reopened at launch; the recent list only offers the others.

## Later: the changes list

The working tree can be a flat list or a folder tree. Click a path to look at it. Add marks more than one, Select all, or Clear. Stage and Unstage apply to the marked paths. Still later: drag between unstaged and staged, discard or delete several paths at once, and stop tracking.

## Not in the session yet

Fetch, push, and fast-forward pull use the user's git and take no credential argument. A pull that is not a fast-forward is refused. The settings watcher is not started. The other adapters (`keyring`, `cache`, `ssh`, `auth`) implement ports and are not constructed by the composition root.
